# NAMEING — חנות מתנות במיתוג אישי (צד לקוח)

אתר לחנות מתנות שמותאמות אישית: הלקוחה בוחרת מוצר, מוסיפה שם או אות, בוחרת צבע וגופן, ומבצעת הזמנה. המנהלת מוסיפה מוצרים וצופה בכל ההזמנות.

| | |
|---|---|
| **האתר החי** | https://nameing-web-client.onrender.com |
| **השרת (API)** | https://ameing-gifts-api.onrender.com |
| **קוד השרת** | https://github.com/Ester-Orzel/ameing-gifts-backend |
| **תיעוד ה-API (Swagger)** | https://ameing-gifts-api.onrender.com/api-docs |

> השרת בחבילה החינמית של Render נרדם כשלא משתמשים בו, ולכן הכניסה הראשונה לאתר יכולה לקחת עד דקה.

## טכנולוגיות

React 19 · TypeScript · Vite · React Router · React Query · React Hook Form · Context API · Axios · **Tailwind CSS v4**

## סוגי משתמשים

| משתמש | מה הוא יכול לעשות |
|---|---|
| אורחת | צפייה במוצרים, חיפוש, סינון ומיון, הוספה לסל |
| לקוחה (`CUSTOMER`) | כל הנ"ל, ובנוסף ביצוע הזמנות וצפייה בהן באזור האישי |
| מנהלת (`ADMIN`) | הוספת מוצרים וצפייה בכל ההזמנות של כל הלקוחות |

### כניסה כמנהלת

אי אפשר להירשם כמנהלת דרך האתר: כל הרשמה יוצרת לקוחה. את המנהלת יוצר השרת בעלייה שלו, לפי משתני הסביבה `SEED_ADMIN_EMAIL` ו־`SEED_ADMIN_PASSWORD` שמוגדרים ב־Render.

| | |
|---|---|
| **אימייל** | `admin@gmail.com` |
| **סיסמה** | `admin123` |

מתחברים בעמוד `/login`, ואז מופיע בתפריט הקישור **ניהול**, שמוביל ל־`/admin`.

> חשבון הדגמה לצורך בדיקת הפרויקט. בחנות אמיתית יש לבחור סיסמה חזקה ולא לפרסם אותה.

**איך מגדירים את המנהלת ב־Render:** בשירות `ameing-gifts-api` נכנסים ל־Environment, מגדירים `SEED_ADMIN_EMAIL=admin@gmail.com` ו־`SEED_ADMIN_PASSWORD=admin123`, שומרים ומפעילים Deploy מחדש. השרת יוצר את המנהלת בעלייה. אם כבר קיימת משתמשת עם האימייל הזה, השרת לא משנה אותה, ולכן יש לבחור אימייל שלא נרשם באתר.

בהרצה מקומית מול שרת מקומי: `admin@example.com` / `Admin1234!`.

## עמודים

| נתיב | עמוד | מי רואה |
|---|---|---|
| `/` | דף הבית: הירו, קטגוריות, מוצרים נבחרים, הדגמת הקלדת שם על מוצר | כולם |
| `/products` | רשימת מוצרים עם חיפוש, סינון לפי קטגוריה ומיון | כולם |
| `/products/:id` | פרטי מוצר והתאמה אישית (טקסט, צבע, גופן) | כולם |
| `/cart` | סל הקניות: שינוי כמות, הסרה וסיכום | כולם |
| `/checkout` | פרטי משלוח ואישור הזמנה | משתמשת מחוברת |
| `/login`, `/register` | התחברות והרשמה | אורחת |
| `/my-account` | ההזמנות שלי | משתמשת מחוברת |
| `/admin` | הוספת מוצר וכל ההזמנות, כולל עדכון סטטוס | מנהלת |

## איך המידע זורם

1. כל קריאה לשרת עוברת דרך פונקציה ב־`src/api.tsx`. שגיאות מהשרת מתורגמות להודעה בעברית דרך `getErrorMessage`.
2. נתונים מהשרת נטענים עם **React Query** (`useQuery`). אחרי שינוי, למשל הוספת מוצר, הרשימה מתרעננת עם `invalidateQueries`.
3. המשתמשת המחוברת והטוקן נשמרים ב־**UserContext** וגם ב־`localStorage`, כך שהכניסה נשארת אחרי רענון. הטוקן נשלח לשרת בכותרת `Authorization: Bearer`.
4. סל הקניות נשמר ב־`localStorage` (`src/cartStorage.ts`). פריטים זהים מתאחדים בסל לשורה אחת עם כמות.
5. הטפסים בנויים עם **React Hook Form**, כולל ולידציה בצד הלקוח (תואמת לכללי השרת) והצגת הודעות שגיאה מהשרת.
6. בהזמנה, הכפתור "אישור הזמנה" ננעל בזמן השליחה, כדי שלחיצה כפולה לא תיצור שתי הזמנות. אחרי הזמנה מוצלחת הסל מתרוקן, ואפשר לבצע הזמנה חדשה. כל הזמנה נשמרת בנפרד.

## ניהול מצב (State)

| מה | איפה נשמר | למה |
|---|---|---|
| משתמשת מחוברת וטוקן | `UserContext` + `localStorage` | נדרשים בהרבה עמודים, ושרדים רענון |
| סל קניות | `localStorage` (`cartStorage.ts`) | הסל קיים גם לאורחת, והמונה ב־Header מתעדכן באירוע `cart-change` |
| מוצרים, קטגוריות, צבעים, גופנים, הזמנות | React Query | טעינה, מטמון ורענון אחרי שינוי |
| ערכי טפסים ושגיאות | React Hook Form | ולידציה והודעות |

## עיצוב (Tailwind)

העיצוב כתוב בקלאסים של Tailwind בתוך הקומפוננטות עצמן. ב־`src/index.css` נמצאים רק הדברים המשותפים לכל האתר:

- **`@theme`:** צבעי המותג, גופנים, צללים ואנימציות. אפשר להשתמש בהם ישירות, למשל `bg-blush` או `text-copper-dark`.
- **`@layer base`:** עיצוב ברירת מחדל לכפתורים, שדות, כותרות וקישורים.
- האתר בעברית וב־RTL (`<html lang="he" dir="rtl">`), ומותאם לטלפון.

| צבע | שימוש |
|---|---|
| `blush`, `blush-deep` | רקעי האתר (שמנת וורוד פודרה) |
| `copper`, `copper-dark`, `copper-light`, `copper-tint` | כפתורים, קישורים, קווים והדגשות |
| `ink`, `body`, `muted` | כותרות, טקסט וטקסט משני (חום שוקולד) |
| `line`, `line-strong` | מסגרות וקווים |

| גופן | שימוש |
|---|---|
| Heebo (`font-sans`) | טקסט האתר בעברית |
| Cormorant Garamond (`font-serif`) | כותרות, מחירים ולוגו |
| Dancing Script (`font-script`) | השם שמוקלד על המוצר בהדגמה |

## הרצה מקומית

### דרישות
Node.js 22 (LTS). לעבודה מלאה צריך גם את [השרת](https://github.com/Ester-Orzel/ameing-gifts-backend) רץ בכתובת `http://localhost:3000`.

### התקנה והפעלה

```bash
npm install
npm run dev
```

בפיתוח, בקשות ל־`/api` מועברות לשרת המקומי (מוגדר ב־`vite.config.ts`). בפרודקשן כתובת השרת נקבעת במשתנה הסביבה:

```
VITE_API_URL=https://ameing-gifts-api.onrender.com
```

### פקודות

| פקודה | מה היא עושה |
|---|---|
| `npm run dev` | שרת פיתוח שמתעדכן בשמירה |
| `npm run build` | בדיקת טיפוסים ובנייה לתיקייה `dist` |
| `npm run lint` | בדיקת קוד |
| `npm run preview` | תצוגה מקדימה של הגרסה הבנויה |

## העלאה ל־Render

אתר סטטי (Static Site) שמחובר לענף `design/ui-refresh` ב־GitHub. כל דחיפה מפעילה בנייה חדשה אוטומטית. ההגדרות בקובץ `render.yaml`:

| הגדרה | ערך |
|---|---|
| פקודת בנייה | `npm install && npm run build` |
| תיקיית פרסום | `dist` |
| משתנה סביבה | `VITE_API_URL` (כתובת השרת) |
| Rewrite | `/*` → `/index.html`, כדי שרענון בעמוד פנימי יעבוד. מוסיפים ב־Render תחת Redirects/Rewrites |

בשרת צריך להגדיר ב־`CORS_ORIGINS` את כתובת האתר, אחרת הדפדפן יחסום את הבקשות.

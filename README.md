# NAMEING — חנות מתנות במיתוג אישי

אתר לחנות מתנות שמותאמות אישית. הלקוחה בוחרת מוצר, מוסיפה שם או אות, בוחרת צבע וגופן ומבצעת הזמנה. המנהלת מוסיפה מוצרים וצופה בכל ההזמנות.

הפרויקט מורכב משני חלקים: **צד לקוח** (המאגר הזה) ו**שרת** (מאגר נפרד).

| | |
|---|---|
| **האתר החי** | https://nameing-web-client.onrender.com |
| **השרת (API)** | https://ameing-gifts-api.onrender.com |
| **תיעוד ה-API (Swagger)** | https://ameing-gifts-api.onrender.com/api-docs |
| **קוד צד הלקוח** | https://github.com/Ester-Orzel/nameing-web-client |
| **קוד השרת** | https://github.com/Ester-Orzel/ameing-gifts-backend |

> השרת בחבילה החינמית של Render נרדם כשלא משתמשים בו, ולכן הכניסה הראשונה לאתר יכולה לקחת עד דקה.

---

## איך המערכת בנויה

```
דפדפן  ──►  צד לקוח (React, אתר סטטי)  ──►  שרת (Express)  ──►  מסד נתונים (PostgreSQL)
```

1. המשתמשת פותחת את האתר, וה־React מבקש מהשרת נתונים (מוצרים, קטגוריות, צבעים וגופנים).
2. בהתחברות השרת מחזיר טוקן (JWT), והלקוח שולח אותו בכל בקשה מוגנת.
3. בהזמנה הלקוח שולח לשרת רק מזהי מוצרים והתאמה אישית. **המחיר מחושב בשרת** לפי המסד, ולא לפי מה שהדפדפן שולח.
4. השרת בודק כל קלט, שומר במסד ומחזיר תשובה. שגיאות חוזרות בעברית ומוצגות למשתמשת.

## סוגי משתמשים

| משתמש | מה הוא יכול לעשות |
|---|---|
| אורחת | צפייה במוצרים, חיפוש, סינון ומיון, הוספה לסל |
| לקוחה (`CUSTOMER`) | כל הנ"ל, ובנוסף ביצוע הזמנות וצפייה בהן באזור האישי. הרשמה באתר יוצרת תמיד לקוחה |
| מנהלת (`ADMIN`) | הוספה ועריכה של מוצרים, וצפייה בכל ההזמנות של כל הלקוחות כולל עדכון סטטוס |

### כניסה כמנהלת

אי אפשר להירשם כמנהלת דרך האתר. את המנהלת יוצר השרת בעלייה שלו, לפי משתני הסביבה שמוגדרים ב־Render ולא נשמרים בקוד.

| | |
|---|---|
| **אימייל** | `admin66140@gmail.com` |
| **סיסמה** | `admin66140` |

מתחברים בעמוד `/login`, ואז מופיע בתפריט הקישור **ניהול**, שמוביל ל־`/admin`.

> חשבון הדגמה לצורך בדיקת הפרויקט. בחנות אמיתית יש לבחור סיסמה חזקה ולא לפרסם אותה.

**איך מגדירים את המנהלת ב־Render:** בשירות `ameing-gifts-api` נכנסים ל־**Environment**, מגדירים `SEED_ADMIN_EMAIL=admin66140@gmail.com` ו־`SEED_ADMIN_PASSWORD=admin66140`, שומרים ומפעילים **Manual Deploy**. השרת יוצר את המנהלת בעלייה ורושם בלוג "נוצר מנהל". אם כבר קיימת משתמשת עם האימייל הזה, השרת לא משנה אותה, ולכן יש לבחור אימייל שלא נרשם באתר.

בהרצה מקומית מול שרת מקומי: `admin@example.com` / `Admin1234!`.

## איך המידע זורם בצד הלקוח

1. כל קריאה לשרת עוברת דרך פונקציה ב־`src/api.tsx`. שגיאות מהשרת מתורגמות להודעה בעברית דרך `getErrorMessage`.
2. נתונים מהשרת נטענים עם **React Query**. אחרי שינוי, למשל הוספת מוצר, הרשימה מתרעננת עם `invalidateQueries`.
3. המשתמשת והטוקן נשמרים ב־**UserContext** וגם ב־`localStorage`, כך שהכניסה נשארת אחרי רענון.
4. סל הקניות נשמר ב־`localStorage` (`src/cartStorage.ts`). פריטים זהים מתאחדים לשורה אחת עם כמות, והמונה ב־Header מתעדכן באירוע `cart-change`.
5. הטפסים בנויים עם **React Hook Form**, כולל ולידציה שתואמת לכללי השרת.
6. בהזמנה הכפתור ננעל בזמן השליחה, כדי שלחיצה כפולה לא תיצור הזמנה כפולה. אחרי הצלחה הסל מתרוקן, ואפשר לבצע הזמנה חדשה. כל הזמנה נשמרת בנפרד.

### ולידציה בטפסים

| טופס | כללים |
|---|---|
| הרשמה | שם מלא, אימייל תקין, טלפון ישראלי (`0` ואז 8 או 9 ספרות), סיסמה של 8 תווים לפחות עם אות וספרה |
| התחברות | אימייל וסיסמה |
| פרטי משלוח | שם מלא, טלפון וכתובת הם חובה. הערות הן אופציונליות |
| התאמה אישית | טקסט, צבע וגופן. מוצר מסוג `INITIAL_ONLY` מאפשר אות אחת בלבד |

## אבטחה

- סיסמאות נשמרות ב־Hash של bcrypt ולעולם לא מוחזרות בתשובות.
- הטוקן (JWT) בתוקף מוגבל, והשרת בודק את המשתמשת והתפקיד מול המסד בכל בקשה.
- `401`: אין טוקן או שהוא לא תקין. `403`: מחוברת בלי הרשאה.
- לקוחה רואה רק את ההזמנות שלה.
- המחיר מחושב בשרת, ושדות לא מוכרים בבקשה נדחים (למשל `role` בהרשמה).
- CORS מוגבל לכתובת האתר (`CORS_ORIGINS`), וכותרות אבטחה עם Helmet.

## עיצוב (Tailwind)

העיצוב כתוב בקלאסים של Tailwind בתוך הקומפוננטות. ב־`src/index.css` נמצאים רק הדברים המשותפים: צבעי המותג, גופנים, צללים ואנימציות (`@theme`), ועיצוב ברירת מחדל לכפתורים, שדות וכותרות (`@layer base`). האתר בעברית וב־RTL, מותאם לטלפון, ומכבד הגדרת "פחות תנועה".

| צבעים | גופנים |
|---|---|
| `blush` (שמנת וורוד פודרה), `copper` (נחושת), `ink` ו־`body` (חום שוקולד), `line` (מסגרות) | Heebo לטקסט, Cormorant Garamond לכותרות ומחירים, Dancing Script לשם שמוקלד על המוצר |

## הרצה מקומית

צריך Node.js 22, ואת [השרת](https://github.com/Ester-Orzel/ameing-gifts-backend) רץ בכתובת `http://localhost:3000`.

```bash
npm install
npm run dev
```

בפיתוח, בקשות ל־`/api` מועברות לשרת המקומי. בפרודקשן כתובת השרת נקבעת ב־`VITE_API_URL=https://ameing-gifts-api.onrender.com`.

| פקודה | מה היא עושה |
|---|---|
| `npm run dev` | שרת פיתוח |
| `npm run build` | בדיקת טיפוסים ובנייה לתיקייה `dist` |
| `npm run lint` | בדיקת קוד |
| `npm run preview` | תצוגה מקדימה של הגרסה הבנויה |

## העלאה ל־Render

**צד הלקוח** הוא אתר סטטי שמחובר לענף `design/ui-refresh`. כל דחיפה מפעילה בנייה אוטומטית.

| הגדרה | ערך |
|---|---|
| פקודת בנייה | `npm install && npm run build` |
| תיקיית פרסום | `dist` |
| משתנה סביבה | `VITE_API_URL` |
| Rewrite | `/*` → `/index.html`, כדי שרענון בעמוד פנימי יעבוד (Redirects/Rewrites ב־Render) |

**השרת** הוא Web Service. בנייתו מריצה התקנה, בנייה, יצירת טבלאות ונתוני הדגמה. המשתנים החשובים שלו: `DATABASE_URL`, `JWT_SECRET`, `CORS_ORIGINS` (כתובת האתר) ו־`SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`. הפירוט המלא ב־README של השרת.
